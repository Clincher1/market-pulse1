# Telegram-поддержка

Интеграция изолирована от рыночных данных и Supabase. API-обработчик находится в
`api/telegram-support.js`, поэтому на Vercel работает как отдельная serverless
функция. Без обязательных серверных секретов обработчик закрыт (HTTP 503), а без
публичного имени бота ссылка не попадает ни в React-интерфейс, ни в начальный HTML.

## Приватность и модель работы

- Посетитель начинает чат с отдельным ботом Market Pulse; личный профиль владельца
  посетителю не показывается.
- Бот передаёт текст обращения в личный чат владельца с ботом. Владелец отвечает
  на карточку обращения, а посетитель получает ответ от имени бота. Запасной формат:
  `/reply ID текст`.
- Для связи ответов используется Telegram ID обращения, указанный только во
  внутренней карточке. База соответствий не создаётся; обращения в Supabase не
  записываются.
- Обработчик не сохраняет и не журналирует содержимое обращений или Telegram ID.
  В HTML сайта ссылка ведёт на same-origin endpoint; только после явного нажатия он
  перенаправляет посетителя на Telegram. Загрузка страниц не обращается к Telegram.
  Telegram обрабатывает сообщения согласно своим правилам и хранит переписку в
  облачном чате.
- Чаты с Telegram-ботами **не являются сквозно зашифрованными секретными чатами**:
  текст виден Telegram и боту. Интерфейс это прямо сообщает; не следует просить
  посетителей присылать пароли, платёжные данные или другие секреты.
- Сейчас принимаются только личные текстовые сообщения до 3500 символов. Файлы,
  группы и каналы не обрабатываются.

## Настройка владельцем

1. В Telegram откройте официальный `@BotFather`, создайте бота с публичным именем
   Market Pulse и сохраните выданный токен **только как секрет**. Выберите username;
   его можно публиковать, токен — нельзя.
2. Напишите новому боту `/start` со своего Telegram-аккаунта. Временно задайте
   токен в локальной переменной окружения `TELEGRAM_BOT_TOKEN` и получите ID:

   ```sh
   node scripts/telegram-support-admin-id.mjs
   ```

   Скрипт печатает только числовой ID из личного `/start`; текст сообщений и токен
   не выводит. До получения ID не публикуйте ссылку на бота.
3. В Vercel Project Settings → Environment Variables задайте для Preview и
   Production (или сначала только Preview):

   - `TELEGRAM_BOT_TOKEN` — токен BotFather, только server-side;
   - `TELEGRAM_SUPPORT_ADMIN_ID` — ID владельца из предыдущего шага;
   - `TELEGRAM_WEBHOOK_SECRET` — случайная строка из латинских букв, цифр, `_` и
     `-`, длиной от 32 символов;
   - `TELEGRAM_SUPPORT_BOT_USERNAME` — username бота для same-origin редиректа,
     без `@`;
   - `VITE_TELEGRAM_SUPPORT_BOT_USERNAME` — тот же публичный username без `@`;
     это публичная build-time переменная, она включает ссылку в интерфейсе.

   **Не добавляйте секреты как `VITE_*`, не вставляйте их в GitHub, исходники,
   PR или переписку.** `VITE_*` предназначен только для публичного username.
4. После публикации проекта безопасно задайте локально те же значения
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`, а также:
   `TELEGRAM_WEBHOOK_URL=https://market-pulse1-eta.vercel.app/api/telegram-support`,
   затем вручную выполните:

   ```sh
   node scripts/set-telegram-support-webhook.mjs
   ```

   Скрипт не печатает токен, секрет или Telegram-ответ. Он только регистрирует URL
   production webhook в Telegram; до запуска ничего не меняет.
5. Проверьте: владелец нажимает `/start` у бота; посетитель открывает кнопку сайта,
   нажимает `/start`, отправляет тестовый текст; он приходит владельцу; ответ на
   сообщение в личном чате владельца с ботом приходит посетителю от бота.

Сначала лучше настроить Preview и проверить весь путь. Production-ссылка появится
после настройки публичного username и новой сборки; webhook настраивается отдельно,
явной командой владельца. Пока настройка не завершена, существующая работа сайта
не зависит от Telegram и не меняется.

## Безопасные границы endpoint

- Только `POST`; сравнение `X-Telegram-Bot-Api-Secret-Token` выполняется constant-time.
- Принимаются только личные сообщения; ответы владельца принимаются только от
  настроенного `TELEGRAM_SUPPORT_ADMIN_ID`.
- Вызовы Telegram API имеют 9-секундный timeout; содержимое, ключи и ответы API
  не попадают в логи приложения.
- При неудачной доставке бот сообщает об ошибке отправителю; сервер не делает
  автоматических повторов, которые могли бы задублировать обращение.
