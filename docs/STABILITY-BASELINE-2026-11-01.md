## Что уже известно про эти числа

1. **`feeds_worst_24h` — не наша поломка.** Google News отвечает `503` примерно
   на шести запросах из десяти. До 01.11.2026 это дополнительно ломалось нашей
   паузой, которая продлевала сама себя (исправлено PR #87). Теперь лента
   спрашивается раз в час и возвращается, как только отвечает `200`.
2. **`ru_insights` 77/80** — три провала 30–31.10, все одиночные: разбор
   российского блока не получил ответа с первого раза.
3. **`asset_history_panel` 53/54** — один провал 01.11 в 07:25: окно между
   миграцией и первым наполнением нового ряда (переход S&P 500 на Yahoo).
4. **`forecasts_fresh`** в окно не входит: код прогнозов остановлен 31.10.2026,
   в истории остались только старые записи. На странице состояния её нет.

## С чем сравнивать через неделю

Не с «зелено/красно», а с этими числами и по правилам из
`docs/TIME-WINDOW-AUDIT.md`:

| Признак | Норма через неделю | Уже поломка |
| --- | --- | --- |
| `checks_7d_ok_pct` | ≥ 99,5 % | < 98 % или падение на 1 п.п. |
| `cron_failed_7d` | 0 | ≥ 1 |
| `cron_runs_7d` | ≈ 4300 ± 5 % | меньше на 10 % — задача не запускается |
| `health_runs_24h` | 24–26 | < 20 |
| `assets_max_cache_age_min` | < 45 | > 60 два замера подряд |
| `assets_max_observation_days` | ≤ 4 (выходные прибавляют 2) | > 6 |
| `feeds_below_90pct_24h` | только Reuters/Google | появилась вторая лента |
| `news_newest_age_h` | < 2 | > 6 |
| одна проверка падает | одиночные провалы — шум | ≥ 2 прогона подряд |

Отдельно смотреть **новые** строки в `checks_7d_trouble`: если там появилось имя,
которого не было в замере выше, — это новый дефект, а не продолжение старого.
