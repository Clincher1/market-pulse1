## 🚨 Блок A. Срочно — безопасность (≈10 минут)

### A1. Отзови старый ключ Twelve Data — СДЕЛАТЬ ПЕРВЫМ
В старой истории коммитов репозитория лежит прежний захардкоженный ключ Twelve.
Раз репозиторий сейчас доступен снаружи — ключ фактически публичен.
Сайт им не пользуется (в Supabase уже стоит новый ключ через секрет `TWELVE_KEY`),
поэтому отзыв ничего не сломает.

1. Открой кабинет Twelve Data → **API Keys**.
2. Найди **старый** ключ (не тот, который ты добавляла в секреты Supabase) → **Delete/Revoke**.
3. Напиши мне «отозвала» — я проверю, что активы на сайте продолжают обновляться на новом ключе.

### A2. Верни репозиторий в Private (после шага B)
GitHub → репозиторий → **Settings → General → Danger Zone → Change repository visibility → Make private**.
Ты открывала его для меня; мне доступ был нужен только на чтение для этой работы — она готова.

## ▲ Блок D. Vercel — переменные окружения (≈5 минут)

1. Vercel → проект → **Settings → Environment Variables**. Задай явно (Production):
   - `VITE_SUPABASE_URL` = URL проекта из Supabase → Settings → API;
   - `VITE_SUPABASE_ANON_KEY` = anon/publishable ключ оттуда же (он публичный, это нормально).
   Так сайт перестанет зависеть от запасного значения в коде.
2. Удали устаревшие переменные, если увидишь (например, `VITE_TWELVE_KEY` — фронт
   Twelve больше не вызывает). Если не уверена в какой-то переменной — спроси меня по имени
   (только имя, не значение!).
3. Сделай **Redeploy** последнего деплоя (или дождись следующего коммита).
