# Бесплатное золото для Market Pulse: практический выбор

Исследование, не переключение production. Проверены официальные страницы и отдельные реальные JSON-ответы. Полный интернет не проверен; доступность из браузера посетителя, SLA и независимая точность цен не установлены. Даты ниже — поля внешних ответов, не подтверждение текущего времени: часть поставщиков вернула ноябрьские даты 2026 года, позднее системной даты сеанса. Такие ответы нельзя автоматически считать свежими или загружать в production.

## Выбор

**Основной вариант для собственного интерфейса: сохранить уже используемый gold-api.com для текущей цены и получать/накапливать историю из того же источника.** Это не требует смены инструмента на фьючерс, чужого iframe, оплаты или передачи пользовательского браузера третьей стороне.

Есть два способа истории:

1. Бесплатный ключ gold-api.com: запросить OHLC завершённых UTC-дней, максимум 10 запросов/час суммарно с /history. Для 30 дней — три часовые квоты при одном запросе на день. Реальные OHLC с ключом ещё не проверены; это путь интеграции, не готовая сертифицированная замена.
2. Без регистрации: сохранять новые валидные наблюдения уже работающего /price/XAU и формировать дневную серию **наших наблюдений**. Это не официальный close поставщика и не восстановление прошлых дней. Пропуски остаются пропусками; достаточная глубина появится постепенно. Правильная подпись обязательна. Изменение относительно последнего нашего наблюдения нельзя выдавать за изменение от чужого дневного close.

Ни один способ не требует уничтожения Twelve Data истории. Её нужно отделить от публичной выдачи, сохранив внутренние записи. Переключение писателя само по себе не очищает старую публичную историю и производные кэши.

**Лучший найденный новый API-кандидат: goldprice.dev.** Он реально вернул дневные spot-бары без ключа. Но это не прямая замена в существующем публичном Supabase JSON: условия запрещают раздачу raw/derived data своим API без отдельного соглашения. Кроме того, требуется проверка дат, закрытия дня и качества. Не следует объявлять его production-ready только из-за успешного JSON.

## Реальные результаты goldprice.dev

Запрос без Authorization:

`https://api.goldprice.dev/v1/bars?symbol=XAU-USD-SPOT&interval=1d&from=2026-10-24&to=2026-11-21&limit=30`

- 21 строка, `next_cursor=null`, `source_id=live_xau_canonical`.
- 20 строк `is_closed=true`; строка 2026-11-20 — false и должна исключаться из завершённой истории.
- Последний close = 3539.3718; /prices вернул 3539.37. Это внутренняя согласованность округления, не независимая верификация рынка.
- Ответ /prices: `contract_type=spot`, `unit=troy_ounce`, `computed_at=2026-11-20T22:08:01.937499+00:00`, source_timestamp=2026-11-20T22:00:00+00:00.
- Даты не согласованы с системной датой сеанса; свежесть не подтверждена. `is_stale=false` не заменяет локальную проверку времени.
- Бар воскресенья сам по себе не ошибка: у spot есть воскресное открытие. Границы торговой сессии и UTC-дня нужно проверять, а не заполнять выходные искусственно.
- Методика описывает медиану семи скорректированных площадок; terms описывает primary + backup. Это ещё один повод не объявлять полную независимую точность или эквивалентность.

Фактическая выборка сохранена в `docs/source-research/goldprice-anonymous-sample.json`; это ограниченная исследовательская выборка, не публичный API/датасет продукта. В файле явно отмечена ручная транскрипция tool-response.

## Точная схема будущего изменения без ежедневного ручного ремонта

1. Один идентификатор серии = инструмент + провайдер + единица + метод дневной точки + timezone. Старые и новые ряды не склеивать.
2. Новые цены проверять на конечность, положительность, timestamp не в будущем и допустимый возраст. `fresh` провайдера недостаточно.
3. Историю загружать отдельно от live, с timeout/backoff и серверным кэшем; провал истории не блокирует другие активы и новости.
4. При невозможности законного показа старой истории закрыть её публичные API/кэши, а не просто спрятать график. Исходные записи не удалять. Для изменения grants/schema — только миграция.
5. Не рассчитывать единый процент из live одного провайдера и close другого без явного определения. Временно не публиковать недоказуемый процент вместо его подмены.
6. Если история ещё не накоплена, не рисовать фиктивный график: показывать доступный ряд и его реальную глубину. Для посетителя можно дать обычную ссылку на GoldBroker/BullionVault — без встраивания сторонних скриптов/cookies.
7. Перед публикацией — тесты неполного дня, неверных timestamp, отказов и квот; два последовательных полных аудита. Сейчас они для нового источника не выполнены.
